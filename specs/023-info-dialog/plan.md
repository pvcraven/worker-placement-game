**Branch**: `023-info-dialog` | **Date**: 2026-05-05 | **Spec**: [spec.md](spec.md)

## Summary

Add a reusable centered informational dialog system to the game client. The dialog supports two modes: auto-dismiss (timed, e.g., 1.5 seconds) and persistent (stays until explicitly dismissed). It is used for round transitions ("ROUND 2" with sound effect), waiting-on-player states ("Waiting on Alice"), and steal notifications ("Alice stole 2 drummers from Bob"). This is entirely client-side — no server changes needed.

## Design

### InfoDialog Component (`client/ui/info_dialog.py`)

A self-contained UI overlay that renders centered text on a semi-transparent background.

**State:**
- `_queue: list[tuple[str, float | None]]` — queued messages with durations (None = persistent)
- `_active_message: str | None` — currently displayed message
- `_active_duration: float | None` — auto-dismiss duration (None = persistent)
- `_elapsed: float` — time accumulated since current message shown
- `_bg_shapes: ShapeElementList` — cached background overlay shapes
- `_text_obj: arcade.Text` — cached text object
- `_dirty: bool` — whether shapes need rebuild (window resize)

**Methods:**
- `show(message: str, duration: float | None = 1.5)` — enqueue a dialog. If nothing is active, display immediately.
- `dismiss()` — dismiss current dialog. If queue has more items, show the next one.
- `update(delta_time: float)` — called from `on_update`. Decrements timer for auto-dismiss dialogs.
- `draw(width: float, height: float, scale: float)` — renders the overlay + text if active.
- `_rebuild_shapes(width: float, height: float, scale: float)` — rebuilds `ShapeElementList` for background.

**Visual Design:**
- Full-screen semi-transparent dark overlay: `(0, 0, 0, 140)` RGBA
- Centered panel: `(20, 20, 30, 240)` RGBA, ~60% window width, ~20% window height
- White text, bold, font size `max(12, int(28 * scale))`, font "Tahoma", centered
- Panel has a subtle light border `(100, 100, 120, 180)` for definition

**Timer Approach:**
- In `update(delta_time)`, accumulate `_elapsed += delta_time`
- When `_elapsed >= _active_duration`, call `dismiss()`
- Simple, no arcade scheduling needed, no callback complexity

### Integration Points in `game_view.py`

1. **`__init__`**: Create `self._info_dialog = InfoDialog()` and load `self._round_sound = arcade.load_sound("client/assets/sounds/sound2.mp3")`

2. **`on_update`**: Add `self._info_dialog.update(delta_time)` call

3. **`on_draw`**: Add `self._info_dialog.draw(w, h, scale)` call after status bar, before `self.ui.draw()` — this ensures the info dialog renders on top of game elements but UIManager dialogs (resource choice, target selection) still render on top

4. **`_on_round_end`**: After updating game state, call:
   ```python
   self._info_dialog.show(f"ROUND {next_round}", duration=1.5)
   arcade.play_sound(self._round_sound)
   ```

5. **`_on_resource_choice_prompt`** (line ~1050): When `pid != my_id`, call:
   ```python
   self._info_dialog.show(f"Waiting on {name}", duration=None)
   ```

6. **`_on_round_start_resource_choice_prompt`** (line ~1230): When `player_id != my_id`, call:
   ```python
   self._info_dialog.show(f"Waiting on {name}", duration=None)
   ```

7. **`_on_intrigue_effect_resolved`** (line ~637): After updating resources, call:
   ```python
   self._info_dialog.show(f"{name} stole {res_str} from {tname}", duration=1.5)
   ```
   (Only for `steal_resources` effect type)

8. **Dismiss waiting dialogs**: In all handlers that resolve a waiting state — when a resource choice resolves, intrigue target resolves, etc. — call `self._info_dialog.dismiss()`. Key handlers:
   - `_on_resource_choice_prompt` when `pid == my_id` (it's now our turn to choose, dismiss waiting)
   - `_update_current_player` when turn advances (waiting is over)
   - Any handler that transitions out of a waiting state

### Waiting State Identification

The "waiting on player" dialog should show when this client receives a prompt/action meant for another player. The dismiss happens when:
- The action resolves (e.g., resource_choice response comes back)
- Turn advances (`_update_current_player` called)
- Round ends

Rather than tracking every possible waiting state explicitly, the simplest approach: show "Waiting on [name]" at the trigger points listed above, and dismiss in `_update_current_player` (which is called after every turn-advancing action) as a catch-all.
